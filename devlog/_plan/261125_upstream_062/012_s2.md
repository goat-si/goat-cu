## Security and behavior

- No new or removed driver tools identified in this range. Refusal `Next:` text and recovery hints change; policy load failures now list no tools. SDK authorization revocation propagates an `end_session` tool error. The protocol unit checks below do not prove binary-level compatibility.
- Desktop keyboard actions place the agent cursor at the focused window or hardware pointer; GOAT's input admission, focus checks, exact targets, process-instance binding and uncertain-delivery/no-resend rules are retained.
- macOS hidden Chromium walks flush pending changes; screenshot capture uses the display filter and vImage. Linux Chromium consent uses native topology and redacted timeout diagnostics; Windows retains GOAT refusal for ambiguous native bubbles.
- Windows avoids changing window style on other Task View desktops and GOAT refuses to continue without its no-activate guard, including when the desktop manager cannot be queried. Desktop keyboard paths refresh the foreground target after cursor animation. Windows ffmpeg uses a job and attempts shutdown; Windows shell children avoid console windows.
- Installer baked pin advances to 0.49.4; GOAT `mcp-config` hint and `connect` removal are retained. Local uninstall changes owned-daemon detection and marker cleanup. OpenJev adds example network adapter code; no new driver telemetry sender was identified.

The vendored telemetry sources, targets JSON and sandbox catalog did not change in the upstream range. `libs/cua/Cargo.toml` changes the inherited SDK version from 0.27.2 to 0.27.4, so the vendored written-out package version and source pointer were updated. The recorded S1 failure shows that `vendor.sh` truncates a target file because its zsh revision expansion is malformed; it was not run again.

An independent source audit identified two unsafe changes and two focus/consent risks. The Xwayland composition fallback is not exposed as an actionable desktop image. The `ax_timeout` hint and Linux click timeout no longer recommend resending while the original operation may still complete; a focused core test failed before the hint correction and passed after it. The Windows prompt matcher keeps GOAT's refusal/revocation behavior, and the desktop key paths refresh the foreground handle after positioning the cursor. macOS hotkey and press_key recheck browser protection after that wait; hotkey and press_key also recheck the admitted PID and kernel process-start stamp at each HID key-down and preserve balanced cleanup after a change, including when base and modifier have the same key code. The OS foreground can still change between a check and the native post; this is not an atomic OS operation. These platform-specific resolutions require Linux/Windows runtime verification in CI or a suitable host.

The independent review also questioned whether two failed base-key release attempts suppress a duplicate modifier's final release. The added `duplicate_base_release_failures_still_send_modifier_release` test observes the actual emitted final modifier-up with cleared flags, even though an internal earlier stack entry remains until the operation ends; it passed in `s2-instance-green.log`. The guard checks foreground and process start immediately before each key-down, but those checks and the OS event post are not atomic.

The step-3 clean-merge review covered complete merged files in the intersection of synthetic base-to-HEAD GOAT changes and this step: core `policy.rs`, `recovery_hint.rs`, `recovery_hint/tests.rs`, `video_ffmpeg.rs`; Linux `capture.rs`; macOS `ax/enablement.rs`, `tools/hotkey.rs`, `tools/scroll.rs`; Windows `browser_consent_ui.rs`, `browser_platform.rs`, `tools/hotkey.rs`, `tools/impl_.rs`, `tools/press_key.rs`, `tools/type_text.rs`. Each file's GOAT-added lines was compared with the merged result; literal presence was not treated as proof of semantics. The independent audits identified the risks and follow-up resolutions above. The remaining intersection paths were conflict resolutions, not clean merges.

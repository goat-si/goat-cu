## Decisions and conflicts

K1: The upstream foreground replay of a re-found target or menu is not installed. Existing GOAT typed-not-delivered routes and scope gates remain; no new step replay is introduced. The upstream `a_found_again_target_refused_in_the_background_falls_back_on_its_fresh_token` test was adapted to `an_unproven_stale_refusal_never_refinds_or_falls_back`: GOAT refuses an untyped stale result after exactly one call. Existing same-session token/window lookup and process-instance protections remain; accepted S1-M1/M2 are not widened here.

K2: The new packaged-app matching is not connected to runtime app/grant association. A manifest application accepts exactly one of bundle_id or executable, and executable pinning occurs only for a path identity; the proposed package family alone cannot establish a trusted-load executable identity. Associating it would widen a grant. Retain GOAT's old behavior, installed-app parser and upstream identity-matching tests; open question: how to bind OS-attested package identity and the approved executable identity together at trusted manifest load. See `/private/tmp/goat-cu-sync62/s10-notes.md`. No display-name or path-prefix grant was introduced.

The upstream matching tests exercise a test-only helper, not the actual app-list assembly or grant authorization. They do not prove the disconnection; that remains a source-review conclusion, and a Windows integration regression test is a follow-up.

K3: combine upstream Linux serve-only stop and PATH-once with GOAT's no-connect behavior and mcp-config hint. K4: take dependency changes while retaining GOAT package version lines.

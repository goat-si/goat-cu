## Binding decisions

- **L1 #8416:** upstream structure adopted, GOAT checks kept; isolation equal or stronger. Registry-owned fast-path state is per runtime and session; ending a session retires its state. Token lookups retain the trusted runtime read session; `forget_window` still removes a replaced window across sessions. GOAT's session and eviction tests are retained with the new argument order.
- **L2 #8159:** GOAT's AXPress-less background click and its gate remain. The background pixel hit-test press route remains gated off. Upstream's advertised-action check adds refusal evidence; no second route follows an uncertain press.
- **L3 #8344:** pid admission occurs after consent; the explicit desktop/pid lane state is combined with GOAT's cross-process file lease, in-process coordinator and retained worker holds. The state reports admission, never grants consent. S7-R1-H1 is not widened.
- **L4 #8434:** an accepted AX text write is never retyped on an uncertain read-back for any web engine. Existing hidden apps are unhidden without activation only by the explicit launch path and only when the returned PID was already present. GOAT's no-reopen-event behavior remains.
- **L5 #7732:** retain at most one trailing Enter and add `enter_uncertain` on an indeterminate send. `enter_pressed` remains false when delivery is uncertain; accepted S7-R1-M1 is not fixed or widened in this step.
- **L6 #8377:** Chromium/Electron background key information is a hint for future actions. A sent unverifiable key carries no foreground retry escalation: an unchanged window cannot prove no action occurred. Two adapted upstream tests failed before this resolution and pass after it.
- **L7 #8365/#8339/#7880/#8469/#8415:** adopt added YAML constraints, removed-flag refusals, responsible-process attribution, Windows non-inheritable sockets and frame-bound zoom. The prior `responsible_ppid` response field is retained as an alias of `parent_pid`; the separate `responsible_pid` is the kernel's responsible process.
- **L8 #8444/#8478/#8093/#8358/#8380/#8370/#8080/#7626:** combine Windows 0.61 API, overlay re-pin, covering-window report, unlocalized names, Linux unresponsive reporting, UIA reference release, producer action records and daemon PID with GOAT's existing protections.

## Security and behavior

No new, removed or renamed callable tool was identified in the source diff. CLI flags `--session-policy`, `--approve-session-policy` and Claude Code compatibility flags are refused; YAML policies gain explicit optional and per-item constraints. Presence metadata gains a permission gate; `check_permissions.source` gains kernel-responsible process information, retaining the old parent PID alias. A verified `bring_to_front` result reports a possible covering ordinary window. Browser typing reports trailing Enter uncertainty. Foreground advice does not cause an automatic retry or license re-sending an uncertain key. Explicit `launch_app` can unhide an already-running app without activation. HTTP sockets accepted on Windows become non-inheritable. **Errata (S11-R1-M1):** At S11 this was not unconditional: the accept/clear race and clear failure could leave sockets inheritable. F5b creates non-inheritable listeners and drops connections when the additional clear fails. Installer baked release advances to 0.56.6; GOAT's no-connect, mcp-config hint and no-mirror choices remain. There is no newly identified telemetry sender or download endpoint in this range.

The vendored telemetry source and two JSON assets did not change from S9's `d9caafdf1` to the target; upstream's shared workspace package version changed to 0.31.0, so the vendored written-out Cargo version and source pointer were updated. The destructive `vendor.sh` was not run; its known unbraced zsh revision expansion remains broken. No target directories were deleted.

Source-only observations needing follow-up: upstream's Linux `app_unresponsive` pending-probe cache is PID-only, so PID reuse while the pending probe remains active may refuse a replacement process; this is an availability refusal, not proof of a wrong-target action. The macOS retained-capture-evidence/Finder and Windows hosted-UWP authorization questions found by the source readers are pre-existing at S10 HEAD, not established S11 losses; neither live behavior nor a grant widening was demonstrated. The single-file Wayland audit also identified the pre-existing S6-P1 paced-typing fallback and partial-progress risks; the relevant functions are unchanged by S11 and remain for the fix slice. A separate partial Linux AT-SPI audit observed that `atspi/native.rs` falls back from the exact PID to a unique same-comm PID, and can discover another bus after an explicit AT-SPI address fails; both are inherited source observations needing identity-boundary triage, not established S11 regressions or runtime reproductions. The same audit saw `atspi/native.rs:6106` fall back to all app frames when an exact window cannot be resolved and `:6511` ignore a selection-clear result before another possible route; both sections are unchanged from S10 HEAD and require OPEN-1/fix-slice triage. The earlier OPEN-1 and OPEN-2 audits and accepted `090_findings.md` remain outstanding. See reader reports for the exact evidence.

## Security and behavior

- Background input capability reporting reflects the actual keyboard gate. No new driver tool was identified; the API result can report a suspected no-op and foreground hint after a complete web observation.
- Background popup checks refuse before the relevant pointer delivery. Existing exact-target, process-instance, session-scoped lookup, no-resend, relocation and cursor-parking rules remain in the GOAT paths. A missing window poll cannot establish no-op.
- Finder inline editor recognition uses its WindowServer parent; Brave default profile detection is extended. Linux desktop capture gains Mutter logical-frame normalization.
- Installer baked release advances from 0.49.4 to 0.49.11; GOAT mcp-config hints remain. No new driver telemetry sender was identified. jev-use examples add browser-provider and receipt code.
- Vendored telemetry, target catalog, sandbox image catalog and inherited vendor crate manifest are unchanged across this range, so no vendor refresh was needed.

An audit found that an unavailable Wayland xdg-output query bypassed GOAT's attested Mutter D-Bus screen-size fallback. The resolver now uses that fallback when the logical query has no result or fails, no X display is set, and the existing D-Bus attestation succeeds; if both reads fail it preserves the logical-query error. A host-side deterministic test failed before the resolution and passed after. This does not verify native Linux compilation or a real GNOME session.

The audit also found that a missing WindowServer window list, missing target in the list, or a popup appearing during cursor animation can defeat the new popup guard. These gaps, along with D3's failed-worker case, remain open for the coordinator's GOAT fix step; the existing pre-step behavior had no popup guard. No claim is made that the guard is atomic with delivery.
